Quick Start — ใช้งานได้ทันทีในหน้าเดียว

ถ้าต้องการดู %โอนเทียบแผนของสัปดาห์ ให้ทำตาม 6 ขั้นนี้ รายละเอียดของแต่ละขั้นอยู่ใน Section 13–16

  1. Login และเลือกสินค้าเข้าสู่ระบบด้วย Username / Password แล้วกดเลือก 🐔 ไก่, 🐷 หมู หรือ 📦 ทั้งหมด
  2. เลือก Weekที่ Dashboard ระบบเลือก Week ที่มีการอัปโหลดล่าสุดให้อัตโนมัติ ถ้าต้องการ Week อื่นให้เปลี่ยนที่ช่อง เลือก Week มุมขวาบน
  3. กรอง Factory / Product (ถ้าต้องการ)ใช้ช่อง ค้นหา... หรือลูกศร ▾ บนหัวคอลัมน์ของตาราง Tracking Data (เช่น ต้นทาง, ปลายทาง, กลุ่มสินค้า) — ไม่มีปุ่ม Search/Apply ระบบกรองทันทีที่เลือก และ KPI ด้านบนจะคำนวณตาม Filter ด้วย
  4. ดู Achievement %คือ %โอนเทียบแผนรวม (Total) สีตัวเลขบอกสถานะ — เขียว = ตามแผน, เหลือง = ต่ำกว่าแผน, แดง = ต่ำกว่าแผนมาก
  5. ถ้าต่ำกว่าแผน → ดูส่วนต่างเทียบ ปริมาณแผนโอน กับ ปริมาณโอนจริงตามแผน และดู มูลค่าสูญเสีย (บาท) จากนั้นเรียงคอลัมน์ % เทียบแผน หรือ สูญเสีย ในตารางเพื่อหาเส้นทางที่มีปัญหา
  6. Drill Down หาสาเหตุคลิกที่แถวในตาราง เพื่อดูรายการ SKU ที่โอนจริงของเส้นทางนั้น ถ้ายังไม่ชัด ไปที่เมนู เพิ่มเติม → ข้อมูลดิบ เพื่อตรวจข้อมูลต้นทาง
ผู้อัปโหลดข้อมูลก่อนดู Dashboard ต้องมีข้อมูล

Upload Data → เลือก Week → อัปโหลด ABS0000 + BSR030 (ไก่) + BDR130 → กด ประมวลผล (ดู Section 13.4)

เมื่อเห็นกล่องสีเหลืองโอนจริงต่างวันจากแผน ±1 วัน

ตรวจรายการแล้วกด ยืนยัน หรือ ไม่นับ — ระบบจะไม่นับรวมจนกว่าจะยืนยัน (ดู Section 10)

ต้องการไฟล์ไปวิเคราะห์ต่อExport Excel

ตั้ง Filter ให้เรียบร้อยก่อน แล้วกด Export Excel ไฟล์จะออกตาม Filter บนหน้าจอ (ดู Section 16)

ข้อที่ผู้ใช้ใหม่เข้าใจผิดบ่อยที่สุด

Achievement % ไม่ใช่ โอนจริง ÷ แผน ระบบนับโอนจริงของแต่ละเส้นทางไม่เกินแผน (ส่วนเกินไม่ชดเชยเส้นทางอื่น) และถ้าขาดไม่ถึง 10% ของแผนให้ถือว่าครบแผน จึงต้องอ่านคู่กับค่า “โอนจริง ÷ แผน (ไม่ปรับ)” ที่แสดงตัวเล็กใต้ตัวเลข — ดู Section 3 และ 7

About This System

ระบบนี้คืออะไร

เว็บไซต์ “ติดตามโอนเทียบแผน” (Tracking โอนเทียบแผน) คือเครื่องมือสำหรับตรวจว่า การโอนสินค้าระหว่างโรงงานที่เกิดขึ้นจริง เป็นไปตามแผนการโอนที่วางไว้หรือไม่ ในแต่ละสัปดาห์ แยกตามวัน โรงงานต้นทาง โรงงานปลายทาง และกลุ่มสินค้า

ผู้ใช้อัปโหลดไฟล์ที่ Export จากระบบ Smart Sales (แผนการโอน และ การโอนจริง) ระบบจะจับคู่แผนกับการโอนจริงให้อัตโนมัติ คำนวณ %โอนเทียบแผน ปริมาณที่ขาด/เกิน และมูลค่ากำไรที่สูญเสียจากการโอนไม่ครบแผน แล้วแสดงเป็น Dashboard

นอกจากนี้ยังมีส่วน “ติดตามการกรอก Supply Daily” ที่ใช้ตรวจว่าโรงงานกรอก Supply รายวันครบหรือไม่ และมีการโอนนอกแผนหรือไม่

ระบบนี้สร้างขึ้นเพื่ออะไร

ตาม README ของโปรเจกต์ ระบบนี้สร้างขึ้นเพื่อ แทนที่ Workflow Excel เดิม (Tracking_โอนเทียบแผน_WK36.xlsx) ปัญหาด้านล่างเป็นปัญหาที่พบหลักฐานในเอกสาร/โค้ดของระบบ

ก่อนมีระบบ (Excel)ปัญหาที่พบระบบช่วยอย่างไร
นำไฟล์ Export มาวางใน Excel แล้วใช้สูตร SUMIFS / Pivot คำนวณเองสูตรลากไม่ครบ — README ระบุว่า Excel เดิมมีบั๊ก “สูตรลากไม่ครบ 7 แถวสุดท้าย” ทำให้ตัวเลขรวม WK36 ต่ำกว่าความจริงคำนวณด้วย Program เดียวกันทุกแถว ทุก Week ไม่ต้องลากสูตร
ไฟล์โอนจริง (ABS0000) Export ได้สูงสุด 5,000 แถว/ไฟล์ ต้องแบ่งหลายไฟล์เสี่ยงลืมไฟล์ หรือวางไฟล์เดียวกันซ้ำจนนับโอนจริงซ้ำรวมหลายไฟล์อัตโนมัติ เตือนเมื่อไฟล์มี 5,000 แถวพอดี และปฏิเสธไฟล์ที่ซ้ำกับไฟล์เดิม ≥ 90%
เส้นทางเดียวกันมีหลายราคาในวันเดียวกันโอนจริงของเส้นทางถูกนับซ้ำทุกแถวราคาแบ่งโอนจริงให้แต่ละราคาตามสัดส่วนแผน ยอดรวมไม่นับซ้ำ
โอนจริงคนละวันกับแผน 1 วันไม่ถูกนับ หรือต้องปรับเองแบบไม่มีบันทึกระบบแนะนำการจับคู่ ±1 วัน ให้ผู้ใช้กดยืนยัน และบันทึกชื่อผู้ยืนยัน
แก้ตัวเลขโอนจริงใน Excel โดยตรงไม่รู้ว่าใครแก้ แก้เพราะอะไร และค่าหายเมื่อนำข้อมูลใหม่มาวางแก้ผ่านหน้าปรับค่า ต้องใส่เหตุผล มีประวัติ (Adjustment Log) และค่าที่แก้ยังอยู่แม้อัปโหลดใหม่

Business Concept — เข้าใจระบบก่อนใช้งาน

อ่านจากบนลงล่าง แต่ละกล่องคือหนึ่งขั้นตอนของงาน และชื่อไฟล์จริงที่เกี่ยวข้อง

1. Supply / Planโรงงานมีสินค้า (Supply) ที่ต้องกระจาย ระบบ Smart Sales แนะนำปริมาณโอน (suggest) แล้วผู้วางแผนปรับเป็นแผนสุดท้าย (supplyAfter)
2. แผนการโอน (Transfer Plan)แผนรายสัปดาห์ BSR030 Weekly (เฉพาะไก่) + แผนรายวัน BDR130 Daily — ระบุวันที่, โรงต้นทาง, โรงปลายทาง, กลุ่มสินค้า, ปริมาณ และราคาต้นทาง/ปลายทาง
3. การโอนจริง (Actual Transfer)ไฟล์ ABS0000_StockTransfers — รายการ SKU ที่โอนจริง วันที่โอน และน้ำหนัก (kg)
4. เปรียบเทียบ Plan vs Actualระบบจับคู่ด้วย วันที่ + โรงต้นทาง + โรงปลายทาง + กลุ่มสินค้า (ไม่ใช้ราคาและไม่ใช้รหัส SKU)
5. %โอนเทียบแผนคำนวณแยก Weekly / Daily / Total โดยนับโอนจริงไม่เกินแผน และปัดขึ้นเป็นครบแผนถ้าขาดไม่ถึง 10%
6. วิเคราะห์ GAPดูปริมาณที่ขาด (Diff แผนโอน), ส่วนที่โอนเกินแผน, กำไรที่ได้ และ “สูญเสียกำไร” (บาท) ของแต่ละเส้นทาง
7. ติดตาม / ตัดสินใจหาเส้นทาง/โรงงาน/สินค้าที่ไม่ตามแผน ใส่หมายเหตุ ยืนยันการโอนต่างวัน และ Export ไปใช้ประชุม
ทำไมไก่กับหมูต่างกัน

สินค้าไก่ใช้แผน 2 แหล่ง (Weekly BSR030 + Daily BDR130) ส่วนสินค้าหมูใช้เฉพาะแผน Daily BDR130 ข้อมูลไก่และหมูแยกกันคนละชุด มี Week ของตัวเอง และไม่นำตัวเลขมารวมกัน แม้ในหน้า “ทั้งหมด” ก็แสดง Dashboard ของแต่ละสินค้าซ้อนกัน

What Does “%โอนเทียบแผน” Mean?

%โอนเทียบแผน คือตัวชี้วัดว่าการโอนจริงสามารถทำได้ ตามแผน มากน้อยเพียงใด โดยนับเฉพาะส่วนที่โอนตรงกับแผน (ส่วนที่โอนเกินแผนไม่ถูกนับเป็นผลงาน)

สูตรที่ระบบใช้จริง

คำขอให้ตรวจสอบสูตร โอนจริง ÷ แผน × 100 — ผลการตรวจสอบจาก Program: ระบบไม่ได้ใช้สูตรนี้ตรง ๆ สูตรจริงใน calcEngine.ts → computeChannel() มี 2 ขั้น คือ ตัดเพดานที่แผน และ ปัดเศษ 10%

%โอนเทียบแผน (ต่อ 1 เส้นทาง)
ขั้น 0 ถ้า แผน ≤ 0 → % = “-” (ไม่มีแผน) ขั้น 1 นับได้ = MIN(โอนจริง, แผน) ← ตัดส่วนที่เกินแผนทิ้ง ขั้น 2 นับตามแผน = • 0 เมื่อ นับได้ = 0 • แผน เมื่อ (แผน − นับได้) < 10% × แผน ← “ปัดหน่วยหยิบ” • นับได้ กรณีอื่น ขั้น 3 %โอนเทียบแผน = นับตามแผน ÷ แผน × 100
ค่าที่ได้อยู่ระหว่าง 0% ถึง 100% เสมอ ไม่มีทางเกิน 100% ส่วนที่โอนเกินแผนแสดงแยกในคอลัมน์ “โอนเกินแผน”
Achievement % (ภาพรวมหลายเส้นทาง)
Achievement % = ผลรวม “นับตามแผน” ของทุกเส้นทาง ÷ ผลรวม “แผน” ของทุกเส้นทาง × 100

Daily คือแผนเสริมบนแผน Weekly ระบบจึงนำโอนจริงไปเติมแผน Weekly ให้เต็มก่อน (README: เดิมนับโอนจริงก้อนเดียวกันให้ทั้งสองช่อง) — % Total ไม่เปลี่ยน

ตัวอย่าง: แผน Weekly = 600 kg, แผน Daily = 400 kg, โอนจริง = 900 kg

ช่องทางแผนโอนจริงที่นับให้ขั้นคำนวณ%

Interpretation: แผน Weekly ทำได้ครบ ส่วนที่ขาดทั้งหมด 100 kg อยู่ที่แผน Daily

7.2 Achievement % และ ปริมาณโอนจริงตามแผน

ความหมาย: %โอนเทียบแผนของกลุ่มแถวที่แสดงอยู่ (ทั้ง Week หรือตาม Filter)

สูตร
ปริมาณโอนจริงตามแผน = Σ “นับตามแผน” ของแต่ละเส้นทาง (คำนวณใหม่ต่อเส้นทาง) Achievement % = ปริมาณโอนจริงตามแผน ÷ Σ แผน × 100 โอนจริง ÷ แผน (ไม่ปรับ) = Σ โอนจริง ÷ Σ แผน × 100 (แสดงตัวเล็กใต้ Achievement %)
“เส้นทาง” ในที่นี้ = วันที่ + ต้นทาง + ปลายทาง + กลุ่มสินค้า (รวมทุกราคาของเส้นทางนั้นเป็นก้อนเดียวก่อนคำนวณ)

7.3 ปริมาณโอนจริง (Actual) และการแบ่งตามราคา

โอนจริงของแต่ละแถวราคา (actual_alloc)
โอนจริงของแถว = โอนจริงทั้งเส้นทาง × (แผนรวมของแถวนี้ ÷ แผนรวมของเส้นทาง) ถ้าเส้นทางไม่มีแผนเลย → แบ่งเท่า ๆ กันตามจำนวนแถวราคา KPI “ปริมาณโอนจริง (Actual)” = Σ โอนจริงของแถว
ตัวอย่าง: เส้นทางเดียวมี 2 ราคา แผน 300 และ 100 kg (รวม 400) โอนจริงทั้งเส้นทาง 360 kg → แถวแรกได้ 270 kg แถวที่สองได้ 90 kg รวมกลับได้ 360 kg พอดี ในตารางจะแสดง “270 kg / 360 kg”

7.4 โอนเกินแผน (Overage)

สูตร
โอนเกินแผน = MAX(โอนจริงของแถว − แผนรวมของแถว, 0)
ตัวอย่าง: แผน 400, โอนจริง 600 → โอนเกินแผน 200 kg · %โอนเทียบแผนยังเป็น 100% เพราะส่วนเกินไม่นับเป็นผลงาน

7.5 กำไรที่ได้ และ สูญเสียกำไร (บาท)

สูตร
กำไรที่ได้ = (ราคาปลายทาง − ราคาต้นทาง) × โอนจริงของแถว สูญเสียกำไร = −MAX(0, แผนรวม − โอนจริงของแถว) × MAX(0, ราคาปลายทาง − ราคาต้นทาง) มูลค่าสูญเสีย (KPI) = Σ สูญเสียกำไร
สำคัญ: “สูญเสียกำไร” ไม่ได้รับการปัด 10% เหมือนคอลัมน์ % — README ระบุว่าตั้งใจให้ตรงกับพฤติกรรม Excel เดิม จึงอาจเห็นแถวที่ % = 100% แต่ยังมีสูญเสียกำไร · ถ้าราคาปลายทางไม่สูงกว่าต้นทาง สูญเสีย = 0 · กำไรที่ได้ไม่ตัดเพดาน (คิดจากโอนจริงทั้งหมดรวมส่วนเกิน)

ตัวอย่าง: แผน 500 kg, โอนจริง 470 kg, ราคาต้นทาง 60 บาท, ราคาปลายทาง 64 บาท

  • %โอนเทียบแผน = ขาด 30 < 50 → 100%
  • กำไรที่ได้ = (64 − 60) × 470 = 1,880 บาท
  • สูญเสียกำไร = −(500 − 470) × 4 = −120 บาท

7.6 ปริมาณ Reject และ % Reject

สูตร
Reject = MAX(Suggest − แผนสุดท้าย (supplyAfter), 0) % Reject = Σ Reject ÷ Σ Suggest × 100 (“-” ถ้า Σ Suggest = 0)
ความหมาย: ส่วนของปริมาณที่ระบบแนะนำแต่ถูกตัดออกตอนปรับแผน — เป็นตัวเลขฝั่งแผนล้วน ไม่เกี่ยวกับโอนจริง · ตัวอย่าง: Suggest 1,200, แผนสุดท้าย 1,000 → Reject 200 kg, % Reject 16.67%

7.7 โอนไม่ตรงแผนเลย

สูตร
โอนไม่ตรงแผนเลย = Σ น้ำหนักโอนจริงของ (วันที่ + ต้นทาง + ปลายทาง + กลุ่มสินค้า) ที่ไม่มีแผนเลยในสัปดาห์ (ไม่รวมรายการ ±1 วันที่ยืนยันแล้ว เพราะย้ายไปนับในแผนแล้ว)
เป็นยอดทั้ง Week เสมอ ไม่เปลี่ยนตาม Filter ในตาราง

หมายเหตุของผู้ใช้คงอยู่เมื่อประมวลผลใหม่ (จับคู่แถวเดิมก่อน ถ้าแถวเปลี่ยนจะรวมหมายเหตุของเส้นทางเดียวกัน)
สิทธิ์การเข้าถึงเมื่อเปิด “บังคับ Login” เฉพาะผู้ใช้ที่ Login และสถานะ active เข้าถึงข้อมูลได้ · ตารางผลลัพธ์แก้ได้เฉพาะหมายเหตุ · แก้โอนจริงได้ผ่านหน้าแก้ไข (มี Log) เท่านั้น · Settings เข้าได้เฉพาะ admin

  • 3
    KPI หลัก — ปริมาณแผนโอน, ปริมาณโอนจริง, Achievement % (สีตามสถานะ + ค่าโอนจริง ÷ แผนแบบไม่ปรับ) และมูลค่าสูญเสีย ปุ่ม ▴/▾ มุมขวาของการ์ดมูลค่าสูญเสียใช้ซ่อน/แสดงแถว KPI รอง (ระบบจำค่าไว้ในเบราว์เซอร์)
  • 4
    KPI รอง — % Weekly (เฉพาะไก่), % Daily, ปริมาณโอนจริงตามแผน (ตัวตั้งของ Achievement %), ปริมาณ Reject / % Reject, โอนไม่ตรงแผนเลย (ยอดทั้ง Week) · วางเมาส์ที่ ⓘ เพื่ออ่านสูตร
  • 5
    กล่อง ±1 วัน — แสดงเมื่อมีรายการรอยืนยันหรือเคยตัดสินแล้ว กด ยืนยัน / ไม่นับ รายแถว หรือ ยืนยันทั้งหมด · ลิงก์ “ตัดสินแล้ว x รายการ” เปิดรายการเดิมพร้อมปุ่ม ยกเลิกการตัดสิน
  • 6
    ตาราง Tracking Data — 1 แถวต่อ วันที่ + เส้นทาง + กลุ่มสินค้า + ราคา · แถวที่ 2 ของหัวตารางคือยอดรวมของแถวที่ผ่าน Filter · ช่องค้นหา, ลูกศร ▾ บนหัวคอลัมน์สำหรับกรอง, คลิกชื่อคอลัมน์เพื่อเรียง, ลากขอบหัวคอลัมน์เพื่อปรับความกว้าง, ปุ่ม คอลัม ▾ ซ่อน/แสดงคอลัมน์, ช่องหมายเหตุพิมพ์ได้
  • 7
    Drill Down — คลิกแถวเพื่อเปิด “รายละเอียด SKU ที่โอนจริงในกลุ่มนี้” คลิกอีกครั้งเพื่อปิด
  • 8
    Export Excel — สร้างไฟล์ตาม Filter ที่ตั้งอยู่ (ดู Section 16)

วิธีใช้งาน

  1. ตรวจ Weekดูหมายเลข ① ว่าเป็น Week ที่ต้องการและไฟล์ครบ (เช่น 3/3) ถ้าไม่ใช่ให้เปลี่ยนที่ ②
  2. อ่าน KPI หลักดู Achievement % และสีของตัวเลข เทียบกับ “โอนจริง ÷ แผน (ไม่ปรับ)” ใต้ตัวเลข
  3. จัดการรายการ ±1 วัน (ถ้ามี)ตรวจว่าเป็นการโอนช้า/เร็วจริงแล้วกดยืนยัน — ตัวเลขจะเปลี่ยนหลังระบบประมวลผลใหม่
  4. กรองตารางเลือกต้นทาง/ปลายทาง/กลุ่มสินค้า/สถานะ จากลูกศร ▾ — KPI ด้านบนจะเปลี่ยนตาม และมีแถบสีฟ้าแจ้งว่า “KPI และ Export คำนวณตาม Filter”
  5. หาแถวที่มีปัญหาคลิกหัวคอลัมน์ สูญเสีย หรือ % เทียบแผน เพื่อเรียง
  6. Drill Down และบันทึกคลิกแถวเพื่อดู SKU · พิมพ์สาเหตุในช่องหมายเหตุ (บันทึกเมื่อคลิกออก)
อ่านหน้านี้อย่างไร
สิ่งที่ต้องดูPlan → Actual → Achievement % → มูลค่าสูญเสีย → สถานะในตาราง
ถ้าเจอปัญหากรอง ต้นทาง → กลุ่มสินค้า → คลิกแถวดู SKU → ข้อมูลดิบ
ถ้าต้องการ Exportตั้ง Filter ก่อน แล้วกด Export Excel

วิธีใช้ Filter

ระบบนี้ไม่มีปุ่ม Search / Apply

ทุก Filter มีผลทันทีที่พิมพ์หรือเลือก และไม่มี Filter แยกช่วงวันที่ — ใช้ Filter คอลัมน์ “วันที่” แทน

Filterอยู่ที่ไหนทำงานอย่างไร
เลือก Weekมุมขวาบน (Dashboard) / ซ้ายบน (หน้าอื่น)Filter หลัก · เปลี่ยน Week แล้ว Filter อื่นในตารางถูกล้างให้อัตโนมัติ
ค้นหา...เหนือตารางค้นหาข้อความบางส่วน (ไม่สนตัวพิมพ์เล็ก/ใหญ่) ใน รหัส/ชื่อต้นทาง, รหัส/ชื่อปลายทาง, กลุ่มสินค้า, หมายเหตุ และหมายเหตุระบบ
▾ บนหัวคอลัมน์ทุกหัวคอลัมน์เลือกค่าเดียวที่ตรงทั้งหมด (เหมือน Filter ของ Excel) · “ทั้งหมด” = ไม่กรอง · คอลัมน์สถานะกรองด้วยชื่อสถานะ · ใช้หลายคอลัมน์พร้อมกันได้ (เงื่อนไข “และ”)
การ์ด Exceptionหน้า Supply Dailyคลิกเพื่อกรองเฉพาะกลุ่มปัญหา
Clear Filterเหนือตาราง ด้านขวาล้างค้นหาและ Filter คอลัมน์ทั้งหมด (และการ์ด Exception) · ปุ่มเป็นสีเทากดไม่ได้เมื่อไม่มี Filter

Filter มีผลกับอะไรบ้าง

  • Dashboard: KPI ทุกการ์ด, ยอดรวมหัวตาราง และ Export คำนวณตามแถวที่ผ่าน Filter — ยกเว้น “โอนไม่ตรงแผนเลย” (ยอดทั้ง Week) · มีแถบสีฟ้า “KPI และ Export คำนวณตาม Filter ในตาราง: x จาก y แถว” เตือน
  • ติดตามโอน: ยอดรวมหัวตารางและ Export ตาม Filter
  • เมื่อ Filter เลือกเฉพาะบางแถวราคาของเส้นทาง ระบบนับโอนจริงตามสัดส่วนของแถวที่เหลือเท่านั้น (ไม่นับทั้งเส้นทาง)

ตัวอย่าง: ดูเฉพาะโรงงานต้นทาง A กลุ่มสินค้าอกไก่

  1. คลิก ▾ ที่หัวคอลัมน์ “ต้นทาง”เลือก โรงงาน A
  2. คลิก ▾ ที่ “กลุ่มสินค้า”เลือก อกไก่
  3. อ่าน KPI ด้านบนคือผลของโรงงาน A กลุ่มอกไก่เท่านั้น
  4. กด Clear Filterเมื่อต้องการกลับไปดูทั้ง Week

วิธีอ่าน Dashboard และ Drill Down

  1. เริ่มจาก KPI Summaryปริมาณแผนโอน กับ ปริมาณโอนจริง บอกขนาดของงานในสัปดาห์ — ถ้าตัวเลขน้อยผิดปกติ ให้ตรวจ “x/y ประเภทไฟล์” ก่อน
  2. ดู Achievement %คือ %โอนเทียบแผนรวม สีบอกสถานะ · ถ้า “โอนจริง ÷ แผน (ไม่ปรับ)” สูงกว่า Achievement % มาก แปลว่ามีเส้นทางที่โอนเกินแผนขณะที่เส้นทางอื่นขาด
  3. ดู GAPแผน − ปริมาณโอนจริงตามแผน = ปริมาณที่ขาด (หลังปัด 10%) · มูลค่าสูญเสียบอกผลกระทบเป็นเงิน · ไก่: เทียบ % Weekly กับ % Daily เพื่อรู้ว่าขาดที่แผนไหน
  4. ดู Breakdownใช้ Filter คอลัมน์ ต้นทาง / ปลายทาง / กลุ่มสินค้า / วันที่ หรือ เรียงคอลัมน์ สูญเสีย จากน้อยไปมาก (ติดลบมากสุดขึ้นก่อน)
  5. Drill Downคลิกแถวเพื่อดู SKU ที่โอนจริง (รหัสสินค้า, ชื่อสินค้า, น้ำหนัก) — ถ้าขึ้น “ไม่มีการโอนจริงในกลุ่มนี้” แปลว่าไม่มีรายการ ABS0000 ที่ตรงกับวันที่+เส้นทาง+กลุ่มนี้
  6. ตรวจสอบ Sourceถ้าตัวเลขผิดปกติ ไปที่ ข้อมูลดิบ → แท็บโอนจริง/แผน กรองวันที่และโรงงานเดียวกันเพื่อดูข้อมูลต้นทาง · ดูหมายเหตุระบบ (±1 วัน) และป้าย “ปรับแล้ว”

19.3 ตัวอย่าง ±1 วัน

  • หลังกด ยืนยัน: แถว 02/09 นับโอนจริง 380 kg → ขาด 20 < 40 → 100% · หมายเหตุเปลี่ยนเป็น “รวมโอนจริงวันที่ 03/09 (โอนช้า 1 วัน) 380 kg — ยืนยันโดย [ชื่อผู้ใช้]” · 380 kg ออกจาก “โอนไม่ตรงแผนเลย”

FAQ

%โอนเทียบแผนคืออะไร?
สัดส่วนของแผนการโอนที่ทำได้ตามแผน คำนวณจากปริมาณที่ “นับตามแผน” (โอนจริงไม่เกินแผน และปัดเป็นครบแผนถ้าขาดไม่ถึง 10%) หารด้วยแผน ดู Section 3
ทำไม % ถึงเกิน 100%?
%โอนเทียบแผนในระบบนี้ ไม่เกิน 100% เพราะตัดเพดานที่แผน ถ้าเห็นค่ามากกว่าแผน ให้ดูคอลัมน์ “โอนเกินแผน” หรือค่า “โอนจริง ÷ แผน (ไม่ปรับ)” ซึ่งเป็นตัวเลขคนละตัว
ทำไมบางรายการไม่มี %?
แผนของช่องทางนั้นเป็น 0 ระบบแสดง “-” และสถานะ “ไม่มีแผน” เช่น แผนที่ถูกปรับเป็น 0 แต่ยังมีค่า Suggest หรือในไฟล์ Export คอลัมน์ % เทียบแผน Weekly ของแถวที่มีเฉพาะแผน Daily · หน้า ติดตามโอน Weekly / Daily ไม่แสดงแถวที่แผนของช่องทางนั้นเป็น 0 ตั้งแต่ต้น
ทำไมโอนจริงน้อยกว่าแผนแต่ได้ 100%?
กฎ “ปัดหน่วยหยิบ”: ขาดน้อยกว่า 10% ของแผนถือว่าครบแผน แต่ “สูญเสียกำไร” ยังคิดจากส่วนที่ขาดจริง
ทำไมตัวเลข Dashboard กับ Detail ไม่เท่ากัน?
สาเหตุที่พบบ่อย: (1) มี Filter อยู่ — KPI คำนวณตาม Filter แต่ “โอนไม่ตรงแผนเลย” เป็นยอดทั้ง Week · (2) หน้า ติดตามโอน Weekly/Daily แสดงเฉพาะแถวที่มีแผนช่องทางนั้น · (3) เส้นทางหลายราคา แต่ละแถวแสดงเฉพาะส่วนของราคานั้น · (4) Achievement % ไม่ใช่ผลรวมโอนจริง ÷ ผลรวมแผน · (5) ข้อมูลดิบ ABS0000 รวมทุกรายการ แต่ Dashboard นับเฉพาะรายการที่ตรงกับแผน
ทำไม % Weekly สูงแต่ % Daily ต่ำ?
ระบบนำโอนจริงไปเติมแผน Weekly ให้เต็มก่อน ส่วนที่เหลือจึงนับให้ Daily ถ้าโอนจริงไม่พอ ส่วนที่ขาดจึงไปแสดงที่ Daily
ข้อมูล Update เมื่อไหร่?
เมื่อมีผู้อัปโหลด/ลบไฟล์ หรือยืนยันรายการ ±1 วัน หรือแก้ไขโอนจริง ไม่มีการดึงข้อมูลอัตโนมัติ ดูเวลาได้ที่ “อัปเดตล่าสุด” · รอบการอัปโหลดมาตรฐาน ต้องตรวจสอบกับ System Owner
ถ้าพบข้อมูลผิดต้องทำอย่างไร?
ไฟล์ผิดทั้งไฟล์ → ลบแล้วอัปใหม่ · ผิดบางเส้นทาง → แก้ไขโอนจริงที่หน้า ติดตามโอน พร้อมเหตุผล · ต้องการอธิบาย → พิมพ์หมายเหตุ · ผิดที่ระบบต้นทาง → แจ้งเจ้าของข้อมูล Smart Sales
รายการ “รอยืนยัน ±1 วัน” ถ้าไม่กดจะเป็นอย่างไร?
ไม่ถูกนับในแผน และยังอยู่ในยอด “โอนไม่ตรงแผนเลย” จนกว่าจะมีคนกดยืนยัน
แก้หมายเหตุแล้ว ประมวลผลใหม่จะหายไหม?
ไม่หาย ระบบเก็บหมายเหตุของผู้ใช้ไว้ทุกครั้งที่ประมวลผลใหม่
ไก่กับหมูรวมกันได้ไหม?
ไม่ได้ ข้อมูลแยกกันคนละ Week หน้า “ทั้งหมด” แสดง Dashboard ของทั้งสองสินค้าซ้อนกัน
